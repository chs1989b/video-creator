# 목소리 선택 + 한국어·영어 나레이션 계획

**목표:** 나레이션 목소리를 4개(여성 2, 남성 2) 중에서 고르고, 대본이 한국어든 영어든 그대로 읽게 한다.
지금은 영어 여성 목소리(Brielle) 1개로 고정. 로드맵 3단계(대사·목소리)의 첫 조각.

**결정 (10/14, 사용자):** 언어 한국어·영어 둘 다, 목소리 남녀 각 2개, 확인용 음성 생성 크레딧 사용 승인.
**브랜치:** `voices` (`source-upload` 위). 커밋은 사용자가 요청할 때만.

## 목소리 고르기 (확인 완료, 2.55크레딧)

Higgsfield 목소리 113개는 이름·ID만 있고 성별·언어 정보가 없다. 후보 10개로 같은 한국어 문장을 만들어
음 높이(기본 주파수 중앙값)로 남녀를 나눴다. 엔진은 ElevenLabs(`variant: elevenlabs`) — 같은 목소리가 한국어·영어를 모두 읽는다.

| 키 | 표시 | 목소리 | 한국어 F0 | 영어 F0 |
|---|---|---|---|---|
| `female-1` (기본) | 여성 1 | Brielle | 225Hz | 188Hz |
| `female-2` | 여성 2 | Hana | 190Hz | 180Hz |
| `male-1` | 남성 1 | Marcus | 132Hz | 116Hz |
| `male-2` | 남성 2 | Ken | 124Hz | 113Hz |

다른 후보: 여성 Elena 222 · Maya 229 · Luna 308Hz, 남성 Julian 142Hz, Andre 167Hz(경계라 제외).
샘플: `worker/data/voice_samples/<키>-<ko|en>.mp3`, 후보 `voice_samples/candidates/` (git 제외). 최종 확정은 사용자가 들어 보고.
비용: 한국어 한 문장 0.15, 영어 한 문장 0.3크레딧 실측 — 영상 1편당 나레이션 비용은 지금과 같은 수준(1회).

## 설계

| 위치 | 바꿀 것 |
|---|---|
| 워커 `pipeline/voices.js` (신규) | `VOICES` 4개, `DEFAULT_VOICE_KEY`, `voiceFor(key)`, `isVoiceKey` |
| 잡 | `voiceKey`(기본 `female-1`, 예전 잡도 기본값) |
| `POST /jobs`, `PATCH /jobs/:id` | `voiceKey` 받기(모르는 키 400/409). 바꾸기는 대본과 같은 규칙 — 나레이션이 돌기 전까지 |
| `stageVoiceover` | `synthesizeSpeech(script, path, { voice: voiceFor(job.voiceKey) })` |
| `GET /voices` | 목록 + 샘플 유무, `GET /voices/:key/sample?lang=ko|en` 샘플 재생(없으면 404) |
| 웹 나레이션 대본 카드 | 목소리 선택(여성 1·2, 남성 1·2) + "미리 듣기"(대본 언어에 맞는 샘플), "한국어/영어 대본으로 읽습니다" 표시 |

## 테스트 (먼저)
- `voiceFor`·기본값·모르는 키, 나레이션 단계가 고른 목소리로 호출되는지, POST/PATCH 검증, `GET /voices` 샘플 유무·샘플 404.
- 웹: 대본 언어 판별(`narrationLanguage`), `createJob`/`updateJobInputs`가 `voiceKey`를 보내는지.
- 브라우저(테스트 모드): 목소리 고르기·미리 듣기 → 완성. 실제 TTS는 위 샘플로 이미 확인했으므로 추가 생성 없음.
