# 원본 영상 파일 업로드 계획

**목표:** 원본 영상을 URL 대신 **파일로 올려서** 작업을 만들 수 있게 한다. URL 방식은 그대로 둔다.

**왜:** "사용 권한이 있는 영상만" 원칙에 맞고(본인 촬영·라이선스 파일), 서버에서 유튜브가 막히는 문제(수강생 배포 로드맵의
위험 항목)를 없앤다. 영상 1편당 추가 크레딧 0.

**브랜치:** `source-upload` (`demo-login` 위). 커밋은 사용자가 요청할 때만.

## 설계

| 위치 | 바꿀 것 |
|---|---|
| 워커 `POST /jobs` | `youtubeUrl` **또는** 파일 `sourceVideo` 중 정확히 하나. 확장자 mp4·mov·m4v·webm만, 최대 200MB(넘으면 413). |
| 워커 `db.createJob` | `sourceVideoPath`(업로드 파일), `sourceVideoName`(원래 파일 이름, 화면 표시용) 저장. URL 작업은 둘 다 null. |
| 워커 `ensureSegments` | `sourceVideoPath`가 있으면 내려받지 않고 작업 폴더에 `source.<확장자>`로 복사해 분할. 없으면 지금처럼 yt-dlp. |
| 웹 `workerApi.createJob` | `sourceVideo` 파일을 받으면 `youtubeUrl` 대신 보냄. |
| 웹 원본 영상 카드 | "링크 / 파일" 전환. 파일을 고르면 미리보기 재생, 파일 이름·크기 표시. "사용 권한이 있는 영상만" 안내. |
| 웹 `middleware.ts` | `/api/worker/*`를 미들웨어 대상에서 제외 — Next.js 15.5는 미들웨어가 걸린 요청 본문을 10MB에서 자름. 중계 경로는 안에서 세션을 직접 확인(로그인 없으면 401)하므로 보호는 그대로. |

## 테스트 (먼저 작성)

- 워커: 파일로 작업 생성(경로·이름 저장, URL null) / 둘 다 없음·둘 다 있음·허용 안 되는 확장자 → 400 / `ensureSegments`가 업로드 파일이면 다운로드를 부르지 않고 그 파일을 분할.
- 웹: `createJob`이 파일을 `sourceVideo`로 보내고 `youtubeUrl`은 안 보냄 / 입력 검사(링크나 파일 중 하나 필요).
- 브라우저(테스트 모드): 로그인 → 파일 업로드(10MB 넘는 파일 포함) → 미리보기 → 승인 → 완성.

## 범위 밖

- 영상 길이 제한(30초)과 사용 권한 동의 체크박스 — "정해야 할 것" 3번(권한 확인 방법) 결정 후.
