# 생성 해상도 선택 (480p / 720p) 계획

**목표:** 작업마다 생성 해상도를 고른다. 480p는 인물 교체 비용이 **57% 싸다**(같은 10초: 480p 30크레딧, 720p 70, 1080p 160 —
10/14 `generate cost` 무료 조회, `ad_multiplier`·Genjutsu 동일). 지금까지는 기본값 720p로만 생성했다.

**결정 (10/14, 사용자):** 진행. 480p 화질 확인용 실제 생성(5초 미리보기 1건 ≈ 15크레딧) 승인. 남은 크레딧은 Task 10(실제 검증)에 쓴다.
**브랜치:** `resolution` (`voices` 위). 커밋은 사용자가 요청할 때만.

## 30초 1편 (미리보기 5회 최악)

| 방식 | 크레딧 | 원화(60원) |
|---|---|---|
| 720p | 5×35 + 25초×7 = 350 | 약 21,000원 |
| 480p | 5×15 + 25초×3 = 150 | 약 9,000원 |

미리보기만 480p로 하고 완성을 720p로 하면 승인한 미리보기를 재사용할 수 없어 0~5초를 다시 만들어야 함(285크레딧) → 이번엔 작업 단위로 한 해상도.

## 설계

| 위치 | 바꿀 것 |
|---|---|
| 워커 `costs.js` | `ad_multiplier` 단가를 해상도별로(480p 3, 720p 7 /초). `estimateCredits(model, { seconds, resolution })`, 기본 720p |
| 잡 | `resolution`(기본 `720p`, 예전 잡도 720p). **작업을 만든 뒤에는 바꾸지 않음** — 승인한 미리보기를 0~5초 구간으로 재사용하므로 |
| `POST /jobs` | `resolution` 받기(480p·720p 외 400) |
| `generate.js` | `--resolution` 전달 |
| 미리보기·나머지 생성 | 잡의 해상도로 생성하고 그 단가로 크레딧 기록, `estimateRemaining`도 |
| 웹 `lib/costs.ts`(신규) | 해상도별 초당 단가·미리보기 비용 한 곳에(지금 Canvas·StageNode·workerApi에 흩어진 7·35 정리) |
| 웹 미리보기 카드 | 작업 전: "화질 480p / 720p" 선택 + 미리보기 1회 비용. 작업 후: 고른 화질 표시(잠김) |

## 테스트 (먼저)
- 워커: 해상도별 단가·기본값·모르는 해상도, `--resolution` 전달, 미리보기·구간 크레딧이 해상도를 따름, POST 검증, 예전 잡 기본값.
- 웹: 단가 함수, `createJob`이 `resolution` 전송.
- 브라우저(테스트 모드), 그다음 실제 모드에서 480p 미리보기 1건으로 화질 확인.
