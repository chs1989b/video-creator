# 유튜브 인물 AI 캐릭터 교체 영상 생성기 — 설계 문서

- 작성일: 2026-09-14
- 상태: 설계 승인 완료, 구현 계획 수립 전 단계
- 맥락: 1:1 수업 결과물로 함께 제작. 1차 목표는 작성자 개인용 도구, 최종 목표는 상용 서비스.

## 1. 배경 및 벤치마킹

Arcads.ai(AI UGC 광고 영상 생성 플랫폼)의 "Workflow" 기능을 벤치마킹 대상으로 조사함. Arcads는 노드 기반 캔버스에서 제품 이미지 → 장면 프롬프트 → Start Frame/End Frame 기반 이미지-투-비디오 생성 → 여러 짧은 클립을 프레임 연속성으로 체이닝하여 하나의 긴 UGC 영상을 만드는 구조였음. 이 "여러 클립을 이어붙여 긴 영상을 만드는" 아이디어를 본 프로젝트의 핵심 파이프라인에 반영함.

## 2. 프로그램 개요

유튜브 URL과 사용자가 업로드한 AI 캐릭터 사진을 입력하면, 원본 영상 속 인물의 표정·입모양·몸동작(모션/퍼포먼스)을 그대로 유지한 채 해당 인물을 사용자가 지정한 AI 캐릭터로 교체한 영상을 생성하는 개인용 영상 제작 도구.

**핵심 제약**: 사용할 생성 엔진(Higgsfield Genjutsu)은 1회 생성 시 4~30초 분량의 모션만 처리 가능하므로, 원본 영상이 이보다 길 경우 여러 개의 세그먼트로 나누어 개별 생성한 뒤 하나로 이어 붙이는 방식이 필요함.

### 범위 (현 단계)
- 입력 영상은 **본인 소유/권한 보유 영상만** 사용 (타인 영상 처리는 범위 밖 — 저작권/딥페이크 규제 검토 필요, §6 참조)
- AI 캐릭터는 **사용자가 업로드하는 사진**으로만 지정 (Higgsfield 프리셋 캐릭터 선택 기능은 범위 밖, 필요 시 추후 확장)
- 개인용 로컬 실행이 목표이며, 상용 서비스 전환은 이후 별도 단계

## 3. 아키텍처

프론트엔드와 워커를 분리한 구조를 채택함 (대안: 단일 로컬 스크립트 — 빠르지만 상용화 시 전면 재작성 필요하여 기각).

```
[웹 UI: Next.js, localhost]  <-- HTTP API -->  [워커: Node.js + Express, 로컬 PC 상시 실행]
                                                        |
                                                        v
                                      yt-dlp / Higgsfield CLI / ffmpeg 호출
```

- **웹 UI**: 유튜브 URL 입력, 캐릭터 사진 업로드, 작업 목록/상태 조회, 완성 영상 미리보기·다운로드
- **워커**: 실제 파이프라인 처리 (아래 §4). 지금은 로컬 PC/맥에서 상시 실행
- 웹 UI와 워커가 HTTP API로 분리되어 있어, 추후 워커만 서버(VPS 등)로 옮기고 웹 UI를 Vercel에 배포하면 상용 서비스 구조로 자연스럽게 전환 가능

## 4. 핵심 파이프라인

1. **다운로드**: `yt-dlp`로 원본 유튜브 영상을 로컬에 저장
2. **세그먼트 분할**: 4~30초 단위로 **끊김 없이 연속** 분할 (세그먼트 N의 마지막 프레임 시점 = 세그먼트 N+1의 시작 프레임 시점이 되도록 정확히 이어서 자름). 원본 길이에 따라 5~10개 세그먼트 발생 예상
3. **세그먼트별 생성**: 각 세그먼트를 모션 레퍼런스로, 사용자가 업로드한 캐릭터 사진을 모든 세그먼트에 동일하게 재사용하여 Higgsfield CLI로 순서대로 생성 요청 → 완료 폴링 → 결과 영상 다운로드
4. **연속성 보정**: 세그먼트를 끊김 없이 연속으로 잘랐으므로 모션 자체는 이론상 이어지지만, AI 생성 특성상 컷 경계에서 미세하게 어긋날 수 있음(§6 미해결 리스크). 완화책으로 세그먼트 연결 시 짧은 크로스페이드를 적용하고, 눈에 띄게 어긋난 세그먼트는 UI에서 표시하여 수동 재생성 가능하게 함
5. **병합**: 완성된 모든 세그먼트 클립을 ffmpeg로 순서대로 이어 붙여 최종 영상 완성
6. **작업 상태 저장**: SQLite(또는 lowdb) 파일 기반 DB에 job 및 세그먼트 단위로 상태(대기/진행중/완료/실패), 입력값, 결과 경로를 기록. 큐 브로커(Redis 등)는 1인용 로컬 도구 규모에 불필요하므로 사용하지 않음

## 5. Higgsfield 연동 방식

- 공식 CLI(`@higgsfield/cli`, `higgsfield auth login`)를 통해 연동. 브라우저 자동화(Playwright)로 유료 웹 UI를 조작하는 방식은 약관 위반 리스크와 UI 변경 시 취약성 때문에 기각함
- Genjutsu 생성 시 입력값: 모션 레퍼런스 영상(세그먼트, 4~30초) + 캐릭터 이미지(최대 49개 슬롯, 매 세그먼트마다 동일한 캐릭터 사진 재사용)
- Higgsfield Genjutsu 웹 UI에는 Arcads처럼 별도의 "시작 프레임" 고정 입력란이 없음을 확인함. 즉 이전 세그먼트의 생성 결과 프레임을 다음 세그먼트에 강제로 앵커링하는 공식 기능은 없고, §4-4의 완화책으로 대응함

## 6. 에러 처리

- Higgsfield 인증 만료 → UI에 "재로그인 필요" 표시, CLI `auth login` 재실행 안내 (자동 재로그인은 시도하지 않음)
- 특정 세그먼트 생성 실패 → 해당 세그먼트만 재시도 가능 (전체 재생성 불필요)
- 유튜브 다운로드 실패(비공개/지역 제한 등) → 원인을 UI에 명확히 표시

## 7. 테스트 전략

- 다운로드, 세그먼트 분할, ffmpeg 병합 로직은 단위 테스트로 분리하여 모킹 검증
- Higgsfield CLI 연동 자체는 자동 테스트보다 실제 계정을 사용한 수동 검증 위주로 진행

## 8. 확인 필요 항목 (구현 착수 전 최우선 검증)

- **[검증 필요] Higgsfield CLI가 Genjutsu 기능을 실제로 지원하는지, 무료 멤버십 한도 내에서 동작하는지.** 공식 사이트에서 CLI/MCP 존재는 확인했으나 Genjutsu 특화 지원 여부는 로그인 후 직접 확인 필요. 미지원 시 Playwright 브라우저 자동화로 폴백

## 9. 알려진 리스크

- **세그먼트 간 연속성 미보장**: §5에서 확인했듯 시작 프레임을 강제 고정하는 공식 기능이 없어, 크로스페이드/수동 재생성 이상의 완벽한 보장 방법이 현재 없음
- **약관 리스크(완화됨)**: 당초 Playwright 자동화 방식은 서비스 약관상 리스크가 있었으나, 공식 CLI 전환으로 대부분 해소됨. 단, §8 검증 결과에 따라 재검토 가능성 있음
- **저작권/딥페이크(상용화 시 재검토 필요)**: 현재는 본인 소유 영상만 다루는 것으로 범위를 제한했으나, 상용 서비스로 확장 시 타인 영상 처리 허용 여부에 대한 법적 검토가 반드시 필요함
