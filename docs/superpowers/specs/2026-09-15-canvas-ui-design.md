# 노드 캔버스 UI — 설계 문서 (서브 프로젝트 1: 캔버스 UI 껍데기)

- 작성일: 2026-09-15
- 상태: 설계 승인 완료, 구현 계획 수립 전 단계
- 상위 맥락: 이 문서는 "Arcads 스타일 노드 에디터"라는 더 큰 목표의 **1번째 서브 프로젝트**만 다룸. 워커 백엔드(`docs/superpowers/specs/2026-09-14-video-creator-design.md`)는 이미 완성·검증됨.

## 1. 배경 및 스코프 결정

사용자가 "Arcads처럼 노드를 드래그해서 연결하는 진짜 에디터"를 요청함. 이는 원래 스펙(§3, 단순 폼+목록 UI)보다 훨씬 큰 작업이라, 3개 서브 프로젝트로 분해함:

1. **캔버스 UI 껍데기** (이 문서) — React Flow 기반으로 노드 드래그·연결·줌/팬이 되는 화면. 실행은 기존 고정 파이프라인 그대로.
2. **백엔드 그래프 실행 엔진** (미래) — jobRunner.js를 "사용자가 그린 임의의 그래프"를 실행하는 범용 엔진으로 재설계.
3. **노드 타입 정의 & 연동** (미래, 2번에 종속) — 개별 파이프라인 단계를 진짜로 조립 가능한 노드로 만들기.

**추가로 논의됐다가 미룬 것**: 캐릭터 사진 1장에서 AI가 좌/우/후면 이미지를 자동 생성해 3D적 캐릭터 참조를 만드는 기능. 실제 Higgsfield에 이런 기능이 있는지 확인 안 됨 (`soul-id`는 5~20장의 기존 사진이 있어야 학습 가능 — "1장에서 시작"이라는 전제와 안 맞음). 크레딧 확보 후 별도 조사·설계 필요. 이번 캐릭터 노드는 사진 1장 업로드로 단순하게 구현하되, 나중에 이 기능을 얹기 쉽도록 캐릭터 입력을 독립된 노드로 분리해둠.

## 2. 이번 서브 프로젝트의 목표

기존 워커 API(`localhost:4000`, 이미 완성됨)를 그대로 사용하면서, `curl` 대신 **Arcads 느낌의 노드 캔버스로 job을 만들고 진행 상황을 시각적으로 확인**할 수 있게 함. 노드 연결선은 자유롭게 드래그해서 바꿀 수 있지만, 실행에는 아직 영향 없음 (사용자 확인 완료 — "혼란 있을 수 있음" 트레이드오프 인지하고 진행하기로 함).

## 3. 아키텍처

- **Next.js 앱** (`web/`, 새 폴더), App Router, 클라이언트 컴포넌트로 캔버스 렌더링
- **React Flow** (`@xyflow/react`) 로 캔버스 구현 (노드 드래그/연결/줌팬 기본 제공)
- 워커 API(`http://localhost:4000`, 이미 CORS 허용됨)를 브라우저에서 직접 `fetch` — 별도 프록시/BFF 없음
- 상태 관리: 현재 활성 job 하나만 추적 (다중 job 이력 관리는 범위 밖). job이 없으면 "대기 중" 상태의 빈 템플릿 노드 5개를 보여줌

## 4. 노드 구성 (고정 5개, 세그먼트별 노드는 만들지 않음)

세그먼트 개수는 원본 영상 길이에 따라 실행 후에야 정해지므로, 이번 단계에서는 세그먼트마다 노드를 동적으로 만들지 않고 **"생성" 노드 하나가 진행률을 집계해서 보여줌**.

| 노드 | 타입 | 내용 |
|---|---|---|
| 영상 입력 | 입력 노드 | 유튜브 URL 텍스트 필드 |
| 캐릭터 입력 | 입력 노드 | 이미지 업로드 (파일 1개) |
| 생성 | 상태 표시 노드 | "대기중 / 다운로드중 / 분할중 / 생성중 (2/3 완료) / 실패" 등 job.status + segments 배열 집계 텍스트 |
| 병합 | 상태 표시 노드 | "대기중 / 병합중 / 완료 / 실패" |
| 결과 | 결과 노드 | 완료 시 `<video>` 미리보기 + 다운로드 링크 (`GET /jobs/:id/result`) |

노드 사이 연결선은 위 순서대로 기본 배치되며, 사용자가 자유롭게 재배치/재연결 가능(시각적으로만, 실행 로직과 무관).

## 5. 실행 흐름

1. 캔버스 위 **"실행" 버튼** 클릭
2. "영상 입력" 노드의 URL 값 + "캐릭터 입력" 노드의 업로드된 파일로 `POST /jobs` (multipart) 호출
3. 응답으로 받은 job id를 상태로 저장, **2초 간격 폴링** (`GET /jobs/:id`) 시작
4. 폴링 결과에 따라 "생성"/"병합"/"결과" 노드의 표시 내용을 갱신
5. `status: 'done'`이 되면 "결과" 노드에 영상 미리보기 표시, 폴링 중단
6. `status: 'failed'`가 되면 "생성" 또는 "병합" 노드에 에러 메시지 표시 (`job.error`), 폴링 중단
7. 세그먼트 재시도는 이번 단계 범위 밖 (워커 API에는 이미 있음 — 나중에 노드에 재시도 버튼 추가 가능)

## 6. 파일 구조

```
web/
  package.json
  next.config.ts
  app/
    layout.tsx
    page.tsx                     # 캔버스 페이지 (클라이언트 컴포넌트)
  components/
    Canvas.tsx                    # React Flow 캔버스 본체, 노드/엣지 상태 관리
    nodes/
      VideoInputNode.tsx
      CharacterInputNode.tsx
      GenerateStatusNode.tsx
      MergeStatusNode.tsx
      ResultNode.tsx
  lib/
    workerApi.ts                  # POST /jobs, GET /jobs/:id 등 fetch 래퍼
```

## 7. 범위 밖 (이번 서브 프로젝트에서 하지 않음)

- 세그먼트별 개별 노드 표시
- 여러 job 동시 관리/이력 목록 UI
- 노드 연결선이 실제 실행 로직에 영향을 주는 것 (서브 프로젝트 2)
- 세그먼트 재시도 버튼
- 캐릭터 멀티앵글 자동 생성 (별도 조사 필요, §1 참고)

## 8. 에러 처리 / 엣지 케이스

- `POST /jobs` 실패(400 등) → 캔버스 상단에 에러 배너 표시, job 생성 안 됨
- 폴링 중 네트워크 오류 → 다음 2초 폴링에서 재시도 (별도 알림 없음, YAGNI)
- 워커 서버가 꺼져 있으면 → 명확한 "워커 서버에 연결할 수 없음" 안내
